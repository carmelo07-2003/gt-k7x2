## 1. いまの全体像

### ファイル
| ファイル | 中身 |
|---|---|
| `index.html` | 画面とアプリ全部（指板・コード・メトロノーム・チューナー・耳コピ）。約100KB |
| `engine.js` | 耳コピの解析エンジン（AIの出力から音・打音を選ぶ、TAB譜の場所を決める、スマホ内学習） |
| `nets.js` | 学習済みの判定器の重み（`TabEngine.setNets(音1段目, 打音, 音2段目, ハーモニクス用)`） |
| `bp.min.js` | Spotify「Basic Pitch」＋TensorFlow.js を1ファイルにまとめたもの（esbuild、約1.1MB） |
| `model/` | Basic Pitch のモデル（model.json＋重み、約0.9MB）とライセンス |
| `tools/` | 判定器を学習し直すためのスクリプト（下の「7. 開発環境」） |
| `docs/開発記録.md` | このファイル |

### 耳コピの解析の流れ（録音モード）
```
録音（48kHz, ScriptProcessor）
 → 22050Hz に変換して音量をそろえる
 → Basic Pitch（AI）: 各フレーム（約11.6ms）×88音の「鳴り始め確率 onsets」「鳴っている確率 frames」
 → engine.js transcribe()
     1) 候補：各音高で onsets の山（0.15以上）
     2) 特徴を計算（23個：AIの確率、エネルギーの立ち上がり、倍音の関係、オクターブの見分け、開放弦かどうか…）
     3) 判定器1段目（小さなニューラルネット）→ 2段目（まわりの判定結果14個も足して判定し直し）
     4) 「ハーモニクスを弾いている」がONなら、ハーモニクス用の判定器に切り替え＋その高さの基準を0.3ゆるめる
     5) 打音：低い帯域（胴の「ボン」）と高い帯域（「パン」）の立ち上がりを別々に見張り、判定器で判定。ドン/パンもロジスティック回帰
     6) スマホ内学習の「補正」を上乗せ（あれば）
 → groupEvents()：0.035秒以内に続いて始まった音を「同時（ジャラーン）」にまとめる
 → assignTab()：ビームサーチでTAB譜の弦とフレットを決める
     （同じ弦は同時に1音／まだ響いている弦は弾いていない／手の移動が少ない／指が届く範囲）
```

### スマホに保存しているもの
| 場所 | キー | 中身 |
|---|---|---|
| localStorage | `gb_earHist` | 今のTAB譜（出来事の列） |
| localStorage | `gb_earRing` | 「前の音の響き」として消した印 |
| localStorage | `gb_learn` | 確認済みの録音の学習材料（最大40本、1本ごとに id・mode） |
| localStorage | `gb_corr` | スマホ内学習の補正（note / perc / harm）と結果の説明 |
| localStorage | `gb_*` | そのほかの設定（チューニング、カポ、感度など） |
| IndexedDB `guitar-aibo` | `session` | 最後の録音（生の音）とAIの出力。開き直しても続きから直すため |

### v4 本人の報告「6弦ばかりの音になる」（〜18:05）

### v5 解析エンジンを作り直し（19:04）— いちばん大きな改訂
- **方針**：決め打ちの時間の規則をやめ、「音の証拠」と「ギターの物理」で判断する。判定は手書きの規則ではなく学習した判定器にする
- **やったこと**
  - テスト用の正解つき音源を作った（本物のアコギのサンプリング音 MusyngKite / FluidR3 のスチール弦。同じ弦を弾き直すと前の音が止まる。スマホの低音カット・部屋の響き・雑音を加える）
    - 手作りの8曲：速いメロディ（1秒10音）、トラヴィス奏法、MOROHA風（ベース連打・叩く・叩きながらジャーン）、ストローク、速いアルペジオ（1秒14音）、スピーカー経由
    - 学習用のランダム演奏：72本（rnd）＋MOROHA風24本（mrh）
  - AIの生の出力を調べた：本物の音の鳴り始め確率は中央値0.75、偽物は大半0.2以下。偽物の正体は倍音（1オクターブ上・1.5オクターブ上）、響いている音の拾い直し、ストロークの混線
  - 判定器：2段のニューラルネット（1段目＝特徴23個、2段目＝＋まわりの判定14個）
  - オクターブの見分け：スマホは低音を拾いにくく、6弦開放（E2）を E3 と間違える → 倍音の並び（低いEなら3倍・5倍の音がある）の特徴を追加
  - 打音：低い帯域と高い帯域の立ち上がりを別々に見張る。AIが「音程のある音としては不採用」にした中途半端な反応が叩いた瞬間に集まる、という特徴も使う
  - TAB譜：ビームサーチ（同じ弦は同時に1音、響いている弦は弾いていない）
  - 再生に合わせてTAB譜が光って追いかける（本人の要望）
- **結果（テスト8曲、F値）**：音 0.663（AI標準の取り出し方）→ 0.880、打音 0.70、ドン/パン 96%、弦の正解率 99.6%

### v6 本人の録音で学習し直し（20:55）
- **本人の録音**：肘の打音、指と手の打音、2弦7F/12F・3弦7F/12F・4弦7F中心のハーモニクス、6弦・5弦開放＋肘（あとで 6→1弦の開放弦も）
- **重要な前提**：本人のギターは **3弦・4弦だけ半音下げ（3弦ファ♯・4弦ド♯）**。最初これを知らず、どの録音にも出る「ファ♯3」を胴鳴りと誤解した → 実は3弦の開放
- **正解の付け方**：打音だけの録音は全部打音。ハーモニクスは「ハーモニクスの高さ・押さえた音（1オクターブ下）・開放弦」のどれが鳴ったかを比べて自動判定。迷うものは学習から外す（ignore）
- **分かったこと**
  - 肘の打音はほぼ見落とし（42回中3回）→ 作った打音と本物がかなり違った
  - 7フレットのハーモニクスが必ず1オクターブ下に出る → AIは正しい高さにも反応していた。私の判定器が捨てていた
- **改善**：本人の録音（前7割で学習・後ろ3割で確認、重み4倍）で学習し直し。「ハーモニクスを弾いている」ON時はハーモニクスの高さの基準を0.3ゆるめる（0〜0.6を比べて0.3が最良）
- **結果（本人の録音の後ろ3割）**：音 0.39→0.76、打音 0.50→0.72、7Fハーモニクスの表示 0/22→20/22

### v7 直した内容から学習（21:17〜21:31）
- **やったこと**：TAB譜を直す（消す・打音にする・高さを直す・＋足す）→「確認済み」→「学習する」（手動を本人が選択）
- **仕組み**：元の判定器のロジット z に「補正」 b + a·z + Σw·特徴 を足す（ロジスティック、強めの正則化）。学習に使っていない分で良くなった時だけ採用
- **失敗→改善**：①打音を「音だった」に直す手段がなかった → 追加。②録音1本だけだと確認できないのに「採用」と出た → 確認できない時は不採用に。③材料が少ないと補正が暴れる → 材料が少ないほど正則化を強く

### v8 開放弦の録音・材料の管理（21:57）
- **本人の報告**：6弦開放がドン判定になる。「音だった」の選択肢に6弦開放がない。学習した材料を1本ずつ直せない。ノイズで打音判定が多い
- **やったこと**：6→1弦の開放弦の録音（12音＋小さな雑音30回ほど）を初期データに追加、「音だった」に開放弦6本を必ず表示（AIが反応した高さに★）、確認済みの録音の一覧（1本ずつ消す・同じ録音は上書き）
- **失敗→改善**：開放弦の倍音（2弦開放の3倍＝ファ♯5）と2弦7Fのハーモニクスが同じ高さ。開放弦向けに学習するとハーモニクスを拾わなくなった → **ハーモニクスモードでは前の（ハーモニクスに強い）判定器に切り替える**
- **結果**：開放弦の録音 12/12、雑音のドン 8→4。本人の録音 音0.780・打音0.771（テスト曲は 0.879→0.860 に少し低下。本人の録音を優先）

### v9 直しやすい画面・ノイズ対策・開き直し（22:21〜22:45）
- **本人の報告**：正しく拾えた音の直後にノイズのドンが出て直す所が多すぎる。再生とTAB譜が離れていて追いかけるのを同時に見られない
- **やったこと**：下に固定の再生バー、TAB譜を上に、列の真下に修正欄、元に戻す、タップで消すモード、打音を全部消す、全部消すは2回押し、打音を拾う量（初期値「少なめ」）、和音の1音だけ消す、弦とフレットで足す、設定変更前の確認、仕上げ中の表示、ハーモニクスモード用の補正を分ける、最後の録音を IndexedDB に保存、学習データの書き出し・読み込み

### v10 響きとノイズを分ける・学習の安全装置（23:03）
- **本人の報告**：響いている途中のノイズを「消す」で学習したら、本物の2弦・3弦開放まで全部「音なし」になった
- **原因**：補正が「音の高さ」「開放弦かどうか」の特徴まで使い、高さごと押し下げた。確認は学習に使っていない分の成績だけで、本物が消えたのを止められなかった

- **確認**：本物と同じ特徴の偽物を大量に消す再現テストで、前の方式は本物4→0、新方式は「100%→58%に減る」として不採用にできた

## 3. 試して失敗・取りやめたこと（同じ失敗をしないために）

| 試したこと | 結果 | 学び |
|---|---|---|
| アーティファクトでマイクを使う | 使えない（サンドボックス） | マイクが要るものは https の自前ページ |
| 曲を流して（スピーカー経由）拾う | 声や歪みで崩れる | 自分で弾いた音で使う前提。YouTube から音を抜くのは規約違反なので勧めない |
| 決め打ちの時間（0.5秒など）で重複・響きを消す | 速い演奏・連打を消す | 時間ではなく「音の証拠」で判断する |
| 「一番強い音だけ残す」 | 指弾きのベースだけ残り6弦ばかり | 新しく鳴った音は全部残す |
| 澄み具合だけでハーモニクスを救う規則 | 偽物を数百拾う | ハーモニクスは本人のスイッチ（モード）で扱う |
| 本人の録音の重みを8倍 | 4倍より悪化（データが少なく揺れる） | 重み4倍 |
| 弾いた直後0.2秒の弱いドンを抑える | 本物の打音（叩きながら弾く）まで消えた（テスト曲の打音 0.68→0.43） | 取りやめ。「打音を拾う量」で対応 |
| 打音の候補の基準を緩める＋大きいネット | 確認用の成績が揺れる | 小さめ（隠れ層12）＋正則化が安定 |
| 響きの拾い直しを3倍重く学習（本体） | 拾い直し 45→18〜26 だが見落としも増え、全体 F 0.83→0.79〜0.82 | 本体は変えず、本人の修正（響きボタン）で少しずつ合わせる |
| 補正に高さの特徴を使う | 「この高さはノイズ」と覚えて本物を消す | 高さ・開放弦の特徴は補正に使わない |

## 5. 既知の課題・次の候補
1. **響きの途中の拾い直し**が一番多い誤り。本人の修正（前の音の響き）をためて、書き出しデータで本体を学習し直すのが本命
2. **弾きながら叩く**（叩きながらジャーン）の打音を取りこぼしやすい。「1拍目は弾く・2拍目は肘」の型の録音があると効く
3. ジャラーン（6本全部）の何本かを取りこぼす
4. 和音の中の1音の「高さを直す」はまだできない（消すのみ）
5. リアルタイムモードは古い判定方式のまま（学習もしない）
6. 録音は ScriptProcessor（将来なくなる可能性）→ AudioWorklet に置き換えるのが望ましい
7. 最初に作ったアーティファクト版（claude.ai 内）は古いまま

### スマホ内学習のデータを本体に取り込む手順（本人から書き出しファイルをもらったら）
- ファイルの `learn[].note[]` は `{z, y, v(37個), w?}`、`perc[]` は `{z, y, v(17個)}`。`mode` が `harm` のものはハーモニクスモード
- `v` の前23個が1段目の特徴、後ろ14個がまわりの判定。1段目は変えずに **2段目と打音の判定器だけ** をこの行を足して学習し直すのが安全（2段目の入力は1段目の出力に依存するため）
- AIが反応しなかった音（候補にない音）は学習できない。録音そのものは入っていない
- 本体を変えたら、スマホの補正は古い判定器向けになるので、リセットされるようにする（未実装。次にやる時に一緒に）

## 6. 本人に関する前提（解析に効くこと）
- チューニング：3弦ファ♯・4弦ド♯（3弦・4弦だけ半音下げ）で録った録音がある。アプリの「設定」→「カスタム」で合わせる必要あり
- LL6 は胴鳴りが大きい（肘の打音は約105Hz・200Hz）。5弦開放（110Hz）・3弦開放と高さが近い
- 叩く音は肘・手のひら・指など。ノイズ（指が離れる音、弦のこすれ）がドン判定されやすい

## 7. 開発環境（判定器を学習し直す時）
`tools/` にスクリプトを置いた（パスは作業環境 `/home/claude/harness` 前提のまま。使う時は書き換える）。データ（音源・AIの出力）は大きいのでリポジトリには入れていない。本人の録音も入れていない（公開リポジトリのため）。

| スクリプト | 役割 |
|---|---|
| `compose.py` / `pieces.py` / `random_pieces.py` | 正解つきのテスト音源を作る（サンプリング音は raw.githubusercontent.com の gleitz/midi-js-soundfonts から取得） |
| `run_bp.py` ＋ `web/bp.html` | ヘッドレス Chrome で Basic Pitch を動かし、AIの出力を `data/*.bp.json` に保存 |
| `label_user.py` / `make_user_gt.py` | 本人の録音に正解を付ける |
| `js/export.js` | 候補ごとの特徴と正解を書き出す（`note` / `perc`） |
| `train_note2.py`（＋`train_note2_lib.py`） | 音の判定器（1段目・2段目）を学習。`UW`＝本人の録音の重み、`SEED`、`RW`＝響きの重み |
| `train_perc.py` | 打音の判定器とドン/パンを学習 |
| `build_nets.py` | `nets.json` → `nets.js` |

### 学習の手順
```
python3 random_pieces.py 0 72      # 学習用の演奏（必要なら）
python3 run_bp.py <名前...>         # AIの出力（1本20〜60秒かかる）
node js/export.js note <全部の名前>
python3 train_note2.py
node js/export.js perc <全部の名前>
python3 train_perc.py
python3 build_nets.py               # → nets.js
node js/eval_user.js ../nets.json   # 確認
```

### つまずいた所
- テスト用のヘッドレス Chrome（SwiftShader）で、録音の長さによって「Failed to compile fragment shader」が出ることがある → 録音を少し短く切ると通る（スマホの実機では関係ない見込み）
- 学習は毎回少し揺れる。複数の SEED で学習して、本人の録音とテスト曲の両方で比べて選ぶ
- `nets.json` の `harm` にはハーモニクスに強い版（v6 の音の判定器）を入れている。音の判定器を学習し直す時は `harm` を上書きしないこと
